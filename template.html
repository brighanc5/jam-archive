New distinction

One performance ≠ one tape

A recording can be an audience tape, a soundboard transfer, a matrix, or an official release. Each has its own provenance and rights status. Our catalog preserves all of them separately.

How the recording index grows

Run the included optional sync_lma.py importer on an Internet-connected computer. It fetches a small, explicitly selected sample of public item metadata, strictly matches the artist field, and flags ambiguous items for manual review. Then rebuild the offline site.

What deserves preservation

Show date, venue, performers, setlist, source type, taper credit, recording lineage, rights status, and the original authorized listening link. Multiple tapes of the same show stay distinct.

The agent workflow

Collect → Match → Investigate → Approve → Publish

Archive metadata can identify a tape without proving exactly which set it contains. Ticketing metadata can suggest an event without proving a guest appearance. Both stay in review until a human checks the evidence.

Queue export timestamp: — · This local website does not itself run the collector, refresh automatically, or send alerts.

What runs automatically?

The command-line agent can query selected artists through the Internet Archive metadata API, optionally retrieve Ticketmaster listings with an authorized API key, deduplicate observations, compare shows with the curated index, and produce this research queue. A prepared GitHub Actions workflow can trigger it on a schedule after deployment; it will not silently publish or generate unsupported claims.

For setup commands and source limitations, see the included README and source_config.json in the complete project.
